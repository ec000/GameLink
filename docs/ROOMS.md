# 房间配置与操作反馈

GameLink 的房间功能由独立的 gamelink-server 提供。ZeroTier 服务负责虚拟网络，ZeroTier 管理后台管理网络及成员；仅安装客户端、MSI 或 Moon/Planet，不会自动在服务器部署 GameLink 房间服务。

## 创建前需要配置

1. 按 [部署说明](../DEPLOYMENT.md) 在 Linux 部署 gamelink-server，配置专用私有网络池、Controller 访问和用户与 Node ID 的绑定，通过 HTTPS 提供客户端访问。现有有其他成员的业务网络不应直接作为房间池。
2. 在「设置 → 房间服务」填写 GameLink Server 的 HTTPS 站点根地址和管理员发放的个人访问凭证。不要填 ZeroTier 后台地址、本地 authtoken.secret 或 Controller 管理 Token。个人凭证仅留在内存中，重启客户端后需重新输入。
3. 在「我的游戏」确认选中游戏配置。正常启动默认选择第一项；创建房间不检查游戏 EXE，不要求提前启动游戏。策略使用优先直连或允许中继，严格直连暂不支持。
4. 在「联机房间」点击创建。服务返回有效房间后，再点连接虚拟网络并等待授权与 IP 分配。

默认 http://127.0.0.1:8080 指当前运行客户端的电脑，只有该电脑确实运行测试房间服务时才适用，不能代表远端 VPS。部署目标、HTTPS 域名、用户和网络池仍需按实际环境准备。

## 点击后的结果（0.6.4）

房间页顶部保留操作状态，失败时显示具体原因，当前页会自动滚动使结果可见。缺少凭证时立即提示并保留房间服务设置入口；地址/凭证格式错误在本地拒绝，不发出创建请求。服务器请求期间显示正在创建/加入/离开，禁止重复操作及修改提交时的服务凭证。失败后恢复按钮；有效响应才显示成功。创建、加入、离开均使用同一反馈区域，完整脱敏事件仍保留在网络诊断页。

连接失败或超时需要核对房间服务部署和地址；401/403 需要核对 GameLink 个人凭证；返回 HTML、错误接口或缺少房间/网络 ID 时不会伪造成功。客户端提示改善不等于已在用户 VPS 部署或验证了真实房间。
